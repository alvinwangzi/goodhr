## 简介
本规范面向 GoodHR 5 的全栈开发团队，覆盖从需求到发布的完整生命周期：需求分析、技术方案设计、代码实现、单元测试、集成测试、文档更新；并明确 Git 分支管理策略、提交信息规范、代码合并流程；提供简化的热重载开发环境（Go Air、Next.js）配置与使用；说明构建脚本、打包发布流程、版本标签管理；以及持续集成与自动化测试执行建议。目标是让每位开发者在统一规范下高效协作，保证质量与可维护性。

**更新** 新增了简化的 PowerShell 开发脚本，大幅降低了开发环境搭建复杂度。

## 项目结构
GoodHR 5 采用云端控制台 + 本地执行器的分层架构：
- 云端后端：Go 服务，负责认证、岗位运行元信息、配置、机器绑定与版本管理等。
- 云端前端：Next.js 控制台，负责用户操作、岗位编排与连接本地 Agent。
- 本地 Agent：运行在用户电脑上的程序，负责浏览器操控、截图、OCR 与本地数据持久化。
- 数据库与缓存：通过简化的 Docker Compose 配置仅运行 PostgreSQL 数据库，前后端在本地开发。

## 性能考虑
- 热重载优化：Air 排除测试文件与无关目录，减少编译时间；Next.js 开发模式启用 Webpack 热更新。
- 构建缓存：Docker 分层缓存、Go build cache、node_modules 与 .next 缓存卷。
- 增量部署：自动部署脚本按变更范围选择构建与服务重启，避免全量重建。
- 资源隔离：容器化部署限制资源使用，便于横向扩展。
- **性能提升**：简化开发环境减少了容器开销，提高开发响应速度。

## 故障排查指南
- **开发脚本问题**：检查 PowerShell 执行权限，确认 Docker 服务正常运行。
- **数据库连接失败**：确认 PostgreSQL 容器已启动且端口 25432 未被占用。
- **后端无法启动**：检查环境变量 GOODHR_PG_DSN 与日志文件路径；确认端口 8084 未被占用。
- **前端无法联调**：核对 NEXT_PUBLIC_CLOUD_API_BASE 配置；确认后端已启动并可访问。
- **部署失败**：查看 auto_deploy.sh 日志；确认当前分支可快进合并且无未提交改动。

**更新** 新增了开发脚本相关的故障排查指导。

### 持续集成与自动化测试
- CI 建议：在 Push/Pull Request 时触发构建与测试，包括 Go 单测、JS/TS 单测与 lint。
- 测试执行：本地先跑单测与集成测试，CI 中执行相同命令保证一致性。
- 报告与告警：生成测试报告并通知失败原因，便于快速定位问题。
