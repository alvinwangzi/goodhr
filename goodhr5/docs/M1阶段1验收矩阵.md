## 账号隔离的当前缺口与下一步

2026-10-08，只读检查页面正常加载的账号信息节点，确认 `/wapi/zpuser/wap/getUserInfo.json` 提供数字 userId 与加密 encryptUserId。仅核对 ID 的类型和是否存在，未输出账号 ID、令牌或联系方式。此节点也出现在正常批量响应中。

Worker 已增加账号 ID 的只读观察与查询；只访问账号节点的 userId，测试使用会抛错的 token 与凭证节点 getter，确认没有访问这些字段。同一主文档出现不同账号 ID 时，候选人身份事实失效并拒绝核对；主文档导航后必须重新取得事实。原生 Edge 的独立响应与 Locator 验证也覆盖账号证明。

最初仅完成账号观察，随后已整体接入以下 1 至 4 项；模块验证通过，仍需第 5 项的整流程验收：

1. 在任何候选人处理前绑定真实账号证明，并在当前运行内拒绝换账号；无证明时不得用默认目录代替。
2. 回复去重、身份映射、未知发送保护、到期安排和复打发送使用一致账号作用域，跨日期保持同一账号的事实。
3. 账号作用域更新时同步改造独立补传器；补传仍使用原 operation_id、原 TaskRun 与原发送事实，不依赖重新打开 Boss。
4. 保留旧默认作用域记录，明确 legacy/待核对处理；不能因为键变了就清空历史、重发或重置次数。
5. 以真实 SQLite、受控页面和本地程序联合验证上述变化，再补齐九项 Windows 场景；任何缺项继续保持 M1 未通过。

本轮已接入实际岗位入口的绑定、动作前账号核对、同一作用域的回复/身份/到期/发送与补传领取。旧收据依据原 TaskRun 的云端所有者、岗位、平台与机器核对后恢复；原编号、原正文和原时间不变。晚返回的旧登录证明不能覆盖新会话。模块证据为 Worker 118 项，以及全部相关 Go 包 `-count=1` 通过；不替代实际程序和 Worker 同一运行的验收。

## 完整 Worker 浏览器证据补充

TestNativeWorkerScanReorderRecovery 已验证同一 Go 运行的列表重排回退：C,D,E 返回时变 E,D,C，进入 resume_rescan，C 不重发，计数保持。TestNativeAgentReceiptProcessRestart 已使用两个真实本地 EXE 进程验证同一 SQLite 的原收据在重新登录后恢复确认；该测试的已发送事实由生产数据库事务创建，未执行候选人页面发送，不冒称完整发送后的崩溃端到端。网页关闭/重开和完整要求审计仍待完成。

TestNativeWorkerThreeActions 已完成同一实际运行中的推荐扫描/打招呼、回复、复打，计数为 3、1、1。TestNativeWorkerTimedScanInterrupt 关闭优先回复，在扫描首人后通过可控检查时钟切入实际消息动作，返回匹配锚点后继续剩余两人；实际动作时间线与检查点计数通过。这补齐三动作安全边界穿插与快续路径，仍需锚点变化回退及进程重启等要求。

同一实际 Go 运行的回复与复打联合场景 TestNativeWorkerReplyAndReGreet 已通过：优先回复 A，再复打 B；同一本地运行与 TaskRun，分别计数一次，原收据上报一次。它只证明两项消息动作的联合，不能替代包含推荐扫描的三动作验收。

复打完整运行新增两项证据：TestNativeWorkerReGreetPositionEnd 与 TestNativeWorkerReGreetLostReceipt。到期后实际页面发送和确认、SQLite 原子队列及 HTTP 收据通过；首次回执丢失时岗位结束后的独立补传保持全部原事实，页面只发送一次。仍需三动作同一运行穿插与进程重启验收，不能以复打单动作代替这些要求。

worker-native-http.test.js 已通过真实 Worker HTTP 路由和实际 CloakBrowser 执行受控页面的提取、三锚点捕获/返回核对、聊天映射、输入/点击及账号变化拒绝。测试输入只作用于虚构按钮，所有网络请求由隔离夹具接管。

同时发现并关闭 SDK humanize 自带页面脚本层，不能仅靠项目源码搜索宣称运行时零注入。此测试覆盖 Worker 层，仍未覆盖完整 Go 岗位执行器的九项 Windows 联合场景，M1 保持未通过。
