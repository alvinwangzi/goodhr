# HRPlus 多电脑执行调度实现规格

日期：2026-10-11。

状态：**下一阶段迭代计划，尚未开发。** 当前先完成 M2 验收。本次只新增 Spec，不修改现有执行锁、接口、数据库或客户端行为。

本规格沿用[执行计划实现规格](执行计划实现Spec.md)及[详细开发计划](执行计划详细开发计划.md)的时间、动作、停止和补传规则，仅扩展集中管理和多电脑执行能力。用户表述中的“H2 plus”按项目名称 **HRPlus** 处理。

## 1 目标及账号区别

人力资源外包公司使用一个 HRPlus 管理账号登录服务端主控台，管理多个招聘计划，把每个计划分配给指定电脑。不同电脑登录不同招聘平台账号时，可以同时执行；主控台集中查看进度、停止任务和读取报告。

| 对象 | 作用 | 示例 |
| --- | --- | --- |
| HRPlus 管理账号 | 登录主控台，管理所属电脑、招聘账号及计划 | 外包公司的管理账号 |
| 执行电脑 | 运行本地程序及浏览器，实际执行招聘动作 | 办公室电脑 A |
| 招聘平台账号 | 在 Boss 等招聘平台登录并招聘 | Boss 招聘账号 A |
| 执行计划 | 保存招聘岗位顺序、动作及工作时间，指定执行电脑与招聘账号 | Java 和测试岗位计划 |

HRPlus 账号和招聘平台账号分别维护。一个 HRPlus 账号可以管理多个招聘平台账号，不能因为它们属于同一个管理账号就全部串行，也不能因此把不同招聘账号的候选人、职位和消息合并。

## 2 已确认范围与工程默认值

### 2.1 已确认方向

1. 一个 HRPlus 账号可在一个主控台管理多台执行电脑和多个计划。
2. 每个计划明确指定一台执行电脑，不随机分配给任意在线电脑。
3. 多台电脑可以分别执行不同岗位和计划。
4. 不同电脑、不同招聘平台账号允许并行。
5. 同一电脑一次只执行一个任务；同一招聘平台账号不能在不同电脑上同时执行。
6. 当前不开发该能力；原 M2 的行为和验收要求保持不变。

### 2.2 第一版工程默认值

以下是本次规划采用的默认方案，实施前仍应在开发评审中核对：

- 一台电脑固定绑定一个招聘平台账号，一个计划的全部执行项属于该平台账号。
- 同一电脑的多个计划排队执行，不同时操作多个浏览器。
- 一个招聘平台账号同一时间只分配给一台执行电脑；更换电脑必须经过安全停止和重新核对。
- 初期保留一个管理账号完成集中操作的使用方式，不要求企业为每台电脑另买或另建 HRPlus 管理账号。
- 主控台退出登录不自动退出所有执行电脑；关闭网页后，已启用的定时安排仍由各电脑本地程序执行。
- 不自动把离线电脑的计划搬到其他电脑；没有确认旧任务结束时不得抢占执行权。
- 复用已有会员功能限制。本规格不新增付费套餐或编造可用电脑数量，商业规则另行讨论。

暂不包括：一台电脑自动切换多个招聘平台账号、多个浏览器同时运行、自动负载均衡、自动迁移未完成任务、服务器代替本地电脑登录招聘平台。

## 3 主控台和本地程序的职责

| 模块 | 职责 | 保留边界 |
| --- | --- | --- |
| 服务端 Go | 保存电脑、账号、计划及分配；校验权限；原子确认资源占用；记录命令、状态、日志和报告 | 不操作招聘网页，不承担候选人处理流程 |
| 主控台网页 | 电脑与账号管理、计划编排和分配、开始/停止、集中查看进度 | 不用网页计时器维持执行，不把按钮受理当作实际开始 |
| 本地 Go | 恢复设备授权，同步自己的计划，定时触发、排队、执行 M1 小步骤及补传 | 保持本机单任务限制，核对当前招聘平台账号和职位 |
| Node 浏览器工具 | 读取页面、定位、点击、输入、滚轮、截图和必要响应观察 | 不计算计划周期，不决定哪台电脑执行，不注入页面脚本 |

各电脑主动连接服务端并获取分配，电脑不必向公网开放本地端口。主控台在 B 电脑上操作时，不使用 B 的 localhost 去控制 A；应通过服务端保存的目标设备命令，由 A 的本地程序接收执行。

## 4 电脑接入与识别

### 4.1 接入流程

1. 管理者在主控台添加执行电脑，生成一次性接入凭证。
2. 执行电脑安装本地程序，输入凭证并确认接入的 HRPlus 账号或组织。
3. 服务端校验凭证后登记设备，签发只属于该设备的授权。
4. 本地程序报告电脑名称、稳定设备编号、程序版本及能力；设备显示在主控台。
5. 在该电脑浏览器中登录招聘平台，本地程序读取并核对实际账号 ID，再确认招聘账号绑定。
6. 管理者为该电脑命名、分配计划；计划符合日期和时段才开始。

一次性凭证需有限期、只能使用一次，并由当前 HRPlus 管理账号签发。具体展示方式可采用接入码，第一版不强制增加二维码或复杂注册流程。

### 4.2 设备授权

- 执行电脑只持有本机授权，不长期保存主控台的完整管理登录令牌。
- 设备授权仅能读取本机分配、领取本机任务、上报原状态、日志和结果；不能管理其他电脑、修改会员或创建任意计划。
- 本地敏感授权沿用 Windows 当前用户保护，接口和日志不得输出明文凭证。
- 撤销设备、换管理账号或授权失效后停止领取新动作，已发动作按安全规则确认或保留 unknown，再结算原任务。
- 主控台退出登录只结束管理会话。设备解绑、退出组织和撤销授权是独立、明确的操作。

### 4.3 电脑显示

电脑列表至少显示：可修改的名称、系统电脑名称、编号末尾、所属 HRPlus 账号、招聘平台及账号标识、程序版本、能力、当前计划和最近连接时间。

“当前浏览网页的电脑”与“目标执行电脑”分别标注。设备编号只是辅助区分，不能作为唯一用户可读名称。

在线状态来自设备连接或心跳，不能把有效绑定、读取绑定接口、最近执行授权校验当作在线证明。无可靠在线证据时显示“状态待核对”。离线不代表旧任务已经结束。

## 5 招聘平台账号与岗位关系

### 5.1 招聘账号登记

- 至少记录平台、内部账号编号、平台稳定账号 ID、用户自定义名称、所属管理账号或组织，以及当前指定电脑。
- 可显示平台账号名称和公司名称帮助区分，但不能据此建立身份映射；同名账号不能合并。
- 密码、Cookie 和平台登录会话保留在执行电脑，不上传到服务端作为集中登录手段。
- 启动及页面安全边界重新核对实际账号与计划绑定；账号变化或无法核对时不发送，保留待核对结果并通知主控台。
- 第一版只开放已有身份核对和动作能力经过验证的平台；没有可靠账号 ID 的平台不能直接宣称支持安全多电脑并行。

### 5.2 岗位配置

计划配置同时包含目标电脑、招聘账号和岗位执行项。不能只保存“电脑 A＋Java 岗位名”。

可复用 HRPlus 岗位筛选模板，但实际招聘平台职位必须属于所选招聘账号，并能唯一核对。不同账号的同名 Java 岗位分别关联，不能按名称套用账号 A 的职位到账号 B。

职位真实标识的读取复用平台现有能力。缺少可靠映射时明确提示待核对，不发送、不猜测；具体平台读取方案在实施评审中验证。

## 6 计划分配及执行流程

1. 保存计划时校验管理权限、设备绑定、招聘账号对应关系、岗位可访问性、动作能力和日期时段。
2. 保存与启用分开，保存不直接启动。用户选择立即开始或按时间执行后登记原意图。
3. 目标电脑同步原计划 ID、配置版本、启用批次及自己的分配；其他电脑不能领取。
4. 本地先检查本机执行通道，再向服务端原子领取设备和招聘账号资源。
5. 两端都允许后，本地核对实际浏览器账号和职位，确认实际开始，再执行已有 M1 步骤。
6. 状态、分动作计数、原 TaskRun、日志和报告持续上报；主控台以已确认事实更新展示。
7. 任务结束或停止后，确认页面安全收尾，再释放资源；重复及迟到回执不能改变新的占用。

主控台命令必须有唯一请求编号、目标设备、计划版本、启用批次、目标原运行及发起人。记录“已受理、待设备确认、执行中、收尾中、已完成或待核对”等事实，重复提交返回原结果。

设备离线时主控台仍可登记停止意图，但不能立即显示“已停止”或允许编辑；恢复连接时先处理停止，再考虑新执行。

## 7 并发资源规则

### 7.1 原子占用

每次执行需同时满足：

- 目标电脑的执行通道空闲。
- 所用招聘平台账号没有其他执行或必要收尾占用。

服务端统一事务确认两项资源；本地继续持有单任务预留。任一项失败，另一项不得留下半份占用。资源校验不能只依赖页面显示、先查后写或心跳时间。

| 场景 | 处理 |
| --- | --- |
| 同一个 HRPlus 账号，电脑 A/账号 A 与电脑 B/账号 B | 允许同时执行 |
| 同电脑、多个计划 | 按原触发时间及稳定序号排队 |
| 不同电脑、同一招聘平台账号 | 不允许同时执行，返回账号资源占用 |
| 不同 HRPlus 用户碰到同一个真实招聘平台账号 | 也不能形成两个独立执行锁；冲突提示不泄露其他组织资料 |
| 电脑或招聘账号仍在收尾 | 继续视为占用 |
| 设备离线或心跳过期 | 显示待核对，不强制释放旧资源 |
| 旧释放或停止确认迟到 | 只匹配原运行、设备、占用编号和凭证，不能清除新占用 |

招聘账号资源使用稳定、已核对的“平台＋平台账号 ID”识别，不能按显示名或 HRPlus 邮箱区分。界面和数据权限仍按 HRPlus 账号或组织隔离；同一真实招聘账号的全局占用判定不扩大数据读取范围。

### 7.2 已有全局锁迁移

当前实现以 HRPlus 用户邮箱锁定一个任务。下一阶段不能直接删除该锁或简单改成 machine_id，否则可能让同一招聘账号在两台电脑重复操作。

- 新设备具备招聘账号身份及资源协议能力后，才启用多电脑并行。
- 老客户端、旧手动任务或身份尚未核对的任务继续使用现有保守限制；不能因为没有新字段就被忽略。
- 开启多电脑模式前，必须确认旧执行和收尾占用已结算。不能以升级或配置开关强制清除旧占用。
- 计划及手动岗位入口使用同一资源规则；手动任务也不能绕过设备或招聘账号锁。
- 新模式关闭时先完成安全收尾，再回到旧限制；保留原请求、运行和待补传记录。

## 8 页面设计

### 8.1 主控台

按电脑展示：名称、状态、招聘平台账号、当前计划/岗位/动作、确认数量、排队原因、最后更新时间和异常提示。汇总显示正在执行、等待、离线及需要核对的设备。

每台电脑分别提供查看计划、查看日志、查看报告和停止操作。主控台不提供未经确认的“强制释放资源”按钮。

### 8.2 电脑与招聘账号管理

提供接入、命名、查看版本/能力、查看绑定关系及撤销接入。解绑前说明影响的计划；运行中先停止并等待确认。电脑离线时显示撤销待确认，不能把旧会话和占用直接当作已清理。

### 8.3 计划页面

- 先选择招聘账号及其指定电脑，再编排可访问岗位。
- 显示设备名称、招聘账号名称及编号辅助信息，不能只列机器码。
- 明确计划目标设备，不按当前浏览网页的电脑自动改写。
- 修改目标电脑或招聘账号属于配置变更，遵循“先停止、确认收尾、再编辑”。
- 更换目标后创建新批次并从第一项开始，不迁移旧扫描游标；旧历史和待补传保持原设备、账号和任务归属。

## 9 保留 M2 的时间、动作及恢复规则

- 计划内名义时段不重叠，计划间可重叠；岗位只排顺序，同岗位可重复。
- 立即开始仅在合法日期和名义时段执行；其他时间等待。
- 3–6 分钟固定随机收尾仅用于已开始工作，不允许启动迟到的新项。
- 同日下个时段沿原进度继续；日末未完成只记录并报告，不暂停周期计划；下个执行日从第一项开始。
- 优先回复、独立复打计时、消息批次公平性及当前工作结束即退出保持 M1/M2 规则。
- prepared/sending/sent/unknown、候选人历史去重、复打次数和原结果补传不因电脑分配改变。
- 候选人身份及去重关联实际招聘账号；相同候选人在不同招聘账号中的会话和联系基准不能误合并。
- 命令、状态和结果失败重试沿原编号及原事实，不重新发送已经确认或待核对的消息。
- 完全离线日使用原启用事实记账，不制造执行权或任务。离线设备恢复后先处理原清理与补传，不补跑往日招聘动作。

## 10 数据与接口规划

优先复用 local_agents、执行计划、请求/占用、TaskRun、检查点、日志和报告；设计前检查已有接口和方法。此处仅定义逻辑数据，不在本次建立表或迁移。

| 数据 | 需要保存的内容 |
| --- | --- |
| 执行电脑 | 管理归属、稳定编号、系统名称、别名、版本/能力、授权状态、连接事实 |
| 设备接入 | 一次性凭证摘要、有效期、使用状态、确认人；不返回长期明文凭证 |
| 招聘平台账号 | 平台、稳定账号 ID、内部编号、名称、归属、指定电脑、核对状态 |
| 计划分配 | 原计划/版本/启用批次、目标电脑、招聘账号及职位关联 |
| 设备命令 | 原请求编号、目标、类型、发起人、受理与执行状态、原回执 |
| 资源占用 | 设备资源与招聘账号资源、原运行/占用者、凭证摘要、收尾状态 |
| 原运行与日志 | 实际电脑、招聘账号、岗位项、TaskRun 和原统计，不套用后来分配 |

接口覆盖设备接入/撤销、名称维护、招聘账号核对、分配、设备同步/命令回执、原子资源领取/释放、集中运行查询。具体路由沿用现有命名，不另建一套同义接口。

所有新增数据库字段有中文备注。新增鉴权需同时校验管理归属、设备授权和原运行资源；不能只相信前端传入的 HRPlus 邮箱、机器码或平台账号 ID。

## 11 实施顺序

1. 完成当前 M2 验收，固定兼容旧客户端的基线。
2. 核对平台账号稳定身份和职位映射，确定第一版实际支持的平台。
3. 增加设备名称、接入/授权和招聘账号绑定；先打通单设备的原流程。
4. 增加设备及招聘账号原子占用，验证旧任务过渡、停止和恢复。
5. 增加计划分配及远程命令，验证主控台不依赖执行电脑的 localhost。
6. 增加多电脑看板、独立日志报告和故障提示。
7. 在两台独立 Windows 电脑的受控环境完成并行、离线和恢复验收，再准备测试版本。

本次不得提前执行上述开发任务。实施任务拆分、版本号和商业并发限制需在下一阶段启动时另行确定。

## 12 验收标准

| 场景 | 必须验证的结果 |
| --- | --- |
| 一个 HRPlus 管理账号绑定两台电脑 | 主控台可读名称、账号和状态，目标设备明确 |
| A/招聘账号 A 与 B/招聘账号 B 同时到点 | 两计划实际并行，各自岗位、动作、数量和 TaskRun 正确 |
| 主控台位于第三台电脑 | 能分别发起和停止 A/B，不操作第三台的本地程序代替目标 |
| 两电脑声称同一个招聘账号 | 同时最多一份执行权，没有重复发送 |
| 同电脑两计划到点 | 一份执行、另一份保留原排队顺序及日志 |
| 两项资源中一项失败或事务回滚 | 无半份占用，不启动页面动作 |
| 后续浏览器切换了招聘账号 | 拒绝操作错误账号，原进度保留 |
| 不同账号有同名职位或同名候选人 | 按原账号及稳定标识核对，统计、会话及去重不误合并 |
| 连点开始、重复命令、回执丢失 | 不重复创建批次、资源或页面动作 |
| 停止一台电脑的计划 | 另一台不同账号的任务继续；目标安全收尾后才可编辑 |
| 关闭或退出主控台 | 已授权电脑的正常定时安排继续 |
| 撤销设备、切组织或授权过期 | 不领取新动作，原结果按安全规则保存与核对 |
| 电脑断网、关机、心跳过期 | 不抢占旧资源、不自动迁移、不把离线当作任务完成 |
| 原电脑恢复或程序重启 | 先确认原运行和清理，补传原结果，不盲目重发 |
| 用户停止并更换目标电脑 | 原历史不改写，新批次从第一项开始 |
| 跨时段、跨日或整天离线 | 沿用 M2 继续、重新开始及原日报告规则 |
| 老客户端或旧手动任务仍运行 | 不被新资源模式绕过，不强制清空旧锁 |
| 查看另一账号或组织的电脑、日志及报告 | 拒绝越权，不泄露其他组织占用者信息 |
| 其他平台能力未验证 | 明确禁用，不回退为猜测账号或脚本注入 |

验收需分别提供数据库事务、真实设备连接、原执行顺序、断网恢复和 Windows 候选版本证据。浏览器仍使用标准 Page/Locator、鼠标、键盘、滚轮和截图；严禁 evaluate、脚本注入、DOM 修改或人为改变页面运行状态。

两台受控电脑通过不等于已验证真实招聘效果或生产环境。不能仅凭设备列表、模拟在线状态、前端按钮或静态构建声称多电脑并行能力完成。
