# HRPlus M2 收尾开发与验收计划

日期：2026-10-11。状态：收尾规划，尚未开始本计划中的修复和新增验收。

依据：[执行计划实现规格](执行计划实现Spec.md)、[详细开发计划](执行计划详细开发计划.md)、[最终验收审计](M2最终验收审计.md)、[进度记录](M2开发与测试进度.md)和[候选安装说明](M2候选安装验收说明.md)。

## 1 目标和范围

完成当前执行计划 M2 的开发环境交付：关闭已确认问题，补齐安装版九项组合验收，固定最终源码、安装包和证据。通过后才宣布 M2 开发验收完成。

已有自动化及受控浏览器专项作为基础证据；0.1.11 已实际安装并核对版本、能力及页面访问，但完整安装版组合尚未验收。最终验收审计中的“安装未执行”已是历史状态，收尾时须更新，不能覆盖原记录或把只读页面检查算作组合通过。

本阶段不开发多电脑分配、招聘账号管理、设备重命名或下一阶段通知协议；不因收尾提前取消当前五秒计划读取。当前账号级单任务保护继续有效。生产发布、真实候选人招聘效果和真实邮件投递单独记录，不包含在本次受控验收通过结论中。

## 3 R0：固定基线和测试条件

1. 核对分支、提交、当前工作区和已安装文件，整理已有 M1/M2 测试记录。下一阶段 Spec 的待提交修改单独保存，不混入停止修复代码。
2. 开始修复前提交已完成的文档修改，遵循新功能前先提交已有工作的项目要求；禁止清理未确认归属的文件。
3. 逐项重核 S2-01 至 S2-11。除安装版九项外，核对 Windows 不同用户登录保护、旧手动入口、静态控制台等是否已有足够证据；缺证据则纳入对应场景，不直接打勾。
4. 使用独立测试数据目录、浏览器 Profile、虚构候选人及测试邮件接收端；沿用隔离 PostgreSQL。安装已获本机会话授权，但每次更新前仍须检查有没有实际运行的任务，不能由安装器按进程名误停任务。
5. 前后端按 dev.ps1 启动，核对候选版本固定的服务地址与测试环境。准备动作台账、原请求编号、运行编号及资源占用查询，支持页面、程序和数据库交叉核对。

## 4 R1：单岗位强制停止修复

已确认的问题是：本地 StopRun 发出取消后立即返回，HTTP 调用随即更新云端 stopped；前端忽略仍在运行及云端同步错误，直接显示停止成功。同一本地 Runner 的浏览器占用虽保留到清理，但云端可能提前放开另一个执行入口。

### 4.1 修复任务

- 先查找已有计划停止、释放、状态通知和待补传方法，优先复用，不创建另一套重复的状态协议。
- 保留原运行和设备校验。强制停止立即取消新动作；已发送动作完成有限确认，无法确认则保存 unknown，不能盲目重发。
- 将“请求被接受”和“已安全退出”分开。只有本地原任务退出、相关执行请求结束且页面清理完成后，才更新云端停止并释放占用。
- 收尾耗时或同步失败不能变成成功回执。采用有界等待或可靠的完成通知/补传；具体选择在修复设计中说明。云端失败沿原运行记录重试，不能清除新的运行占用。
- 前端核对停止返回结果和云端确认事实；未确认前不显示“已强制停止”。按用户决定，暂不增加“正在停止”的新按钮设计，可沿用现有按钮并给出待确认提示，避免重复开始。
- 核对正常停止与计划停止是否受相同问题影响；仅修复同一根因，不扩展下一阶段多电脑功能。

### 4.2 必须验证

| 场景 | 预期 |
| --- | --- |
| 普通强制停止 | 立即取消，安全退出后停止完成、释放原占用 |
| 页面收尾被故意延迟 | 延迟期间云端仍忙；手动入口和计划不能抢占 |
| 已发消息确认超时 | unknown 持久保留，不重发；安全退出后可释放，不等待所有日志上传 |
| 本地已退出但云端请求失败 | 前端不报确认成功，云端保持待核对，原编号可恢复同步 |
| 旧停止、旧释放迟到 | 不取消新运行，不清除新占用 |
| 点击停止后刷新页面 | 从已确认事实恢复按钮，不靠页面临时状态判断 |
| 操作请求卡住或本地程序退出 | 核对 Node 原请求是否仍发动作；无法证明安全退出时不释放资源 |

## 5 R2：回归与证据检查

1. 为停止问题先建立可失败的针对性测试，再验证修复；必须覆盖真实收尾延迟和占用竞争，不能只断言 cancel 被调用。
2. 运行受影响的本地 positionrunner、planrunner、浏览器取消、云端停止/占用和前端状态测试。
3. 在明确设置隔离 PostgreSQL 测试参数后验证事务、停止与领取竞争、旧回执保护。保留通过/失败/跳过记录及测试数据库来源。
4. 最终候选运行本地与云端 Go、Node、前端相关完整套件及构建。原生 Windows 专项须显式启用，不把默认跳过写成通过；已通过且未受影响的昂贵专项可引用固定基线证据，注明版本和理由。
5. 检查零脚本注入约束、敏感凭证日志、数据库中文备注及 git diff --check。出现新修改后重跑受影响检查，不沿用修改前结果。

## 6 R3：最终候选构建与安装

- 修复和必要测试提交后固定源码；按既有版本流程选择高于当前 0.1.11 的开发候选版本，构建前核对，不在此预定版本号。
- 使用现有 Windows 打包脚本，记录源码提交、环境、固定公开地址、版本、安装包和关键文件 SHA256。
- 确认无任务运行后安装，不自动恢复用户已有安排。启动已安装 EXE 的隔离测试数据目录，验证 Worker 与控制台来自当前安装文件。
- 记录安装日志、实际版本、能力、前端/后端访问、静态控制台及原手动入口。不能以源码目录直接启动的程序代替实装 EXE。
- 受控页面必须通过真实安装程序和标准浏览器动作执行。测试适配不能放宽生产权限、身份和释放校验，不能向招聘页面注入脚本。

## 7 R4：安装版九项组合验收

| 编号 | 场景 | 必须留存的结果 |
| --- | --- | --- |
| 1 | Windows 安装及 M1 旧入口回归 | 实装版本、控制台、手动任务与浏览器可用；登录保护专项证据及缺口核对 |
| 2 | Java 扫描 → 销售扫描 → Java 回复 → 销售回复 | 顺序正确，后项不提前动作，各项 TaskRun 和数量独立；追加同岗位重复项 |
| 3 | 同岗位扫描、回复和复打 | 新回复与到期复打安全穿插，计数正确，无重复发送 |
| 4 | 短窗口、固定随机收尾、下午继续、日末及次日 | 3–6 分钟抽样持久，原进度继续，未完成日报保留，周期计划次日从第一项开始 |
| 5 | 停止 → 确认 → 编辑 → 再开始 | 未安全停止不能编辑或抢占；新运行从第一项开始，原历史和待补传不丢失；覆盖强制停止 |
| 6 | 时段外立马开始 | 只等待，没有招聘动作；到合法时段重新核对再执行 |
| 7 | 关闭网页、退出/重启本地程序 | 有效登录可恢复安排；按原运行和原批次恢复，不重复领取；失效登录不绕过校验 |
| 8 | 断网、unknown、补传、旧回执及邮件不可用 | 不重发，计数不重复，历史不改写；报告失败不阻止次日；整天离线也有原事实日报 |
| 9 | 平台能力与默认 Profile | 仅开放已支持动作，未知/关闭平台拒绝，账号和 Profile 不串用；配置校验不能冒充各平台真实网站验收 |

每项记录源码、包摘要、实装程序、数据环境、操作步骤、预期/实际、运行与请求编号、日志/截图/动作台账及数据库结果。短窗口和次日可以使用隔离环境的受控时钟，并明确标注，不能声称真实等待了整天。

九项需使用同一最终候选。验收发现缺陷则修复、递增候选并重做受影响组合；无影响的项目通过差异分析保留证据。真实招聘网站人工复测若涉及实际发送动作，单独确认测试账号和允许范围；受控验收不自动授权联系真实候选人。

## 8 R5：复审、记录与完成判定

1. 独立 Agent 对固定最终提交复审停止、占用、恢复及验收证据；修复阻塞问题后对新提交重新复审。
2. 更新最终验收审计、开发进度和候选安装说明：当前版本、九项结果、通过/跳过、残留限制及日志位置一致，历史证据保留。
3. 将修复、测试和文档提交并推送当前开发分支；保留必要生成包，不提交用户数据或构建噪声。确认本地分支干净及远程提交一致。
4. 给出开发环境交付说明：安装版本、源码提交、包摘要、访问地址、验收结论、已知限制和回退方式。测试环境发布与生产发布需独立安排，不以本地安装代替部署。

只有已确认停止问题关闭、M1 回归成立、九项安装版组合通过、必要数据库和最终构建检查通过、独立复审无阻塞、文档与候选一致时，才可标记 M2 开发验收完成。任何缺证据或被跳过的必测项继续列为未完成，不靠“基本可用”关闭阶段。
