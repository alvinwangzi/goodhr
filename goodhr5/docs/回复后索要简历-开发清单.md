# 回复后索要简历开发清单

更新时间：2026-09-22

## 背景

- Boss 直聘规则：候选人回复前，聊天框里的"索要简历/手机号/微信"按钮是禁用态，打招呼后立即索要必然失败。
- 新流程：打招呼成功时把候选人记入本地"待索要名单"，岗位停止或完成收尾时自动切到消息页逐人检查回复；已回复者点击"求简历"并补报云端，未回复者保留名单下次岗位收尾再查。
- 收尾检查在后台协程执行，不阻塞岗位停止/完成的返回；只对勾选了索要项（手机号/微信/简历）的岗位生效，只配置追加问候语的岗位维持原即时流程。
- 本期只做最小闭环：不对未回复候选人发送追加问候语（对方已回复场景由消息页判断，避免重复打扰）。

## 页面事实（2026-09-22 探测确认）

- 消息页地址 `zhipin.com/web/chat/index`，左侧"沟通"菜单在同 SPA 内，文本定位"沟通"后轮询 URL 判断切换成功。
- 会话项选择器 `[class*='user-list'] [class*='item']`，同一会话有三层嵌套 item，取第一个可见项（文本最全：时间+未读数+名字+职位+预览）。
- 回复判断：会话项文本含 `[送达]` 或 `[已读]` 表示我方最后一条消息未被回复；否则视为对方已回复或发过文件。
- "求简历"按钮用文本定位（右侧会话面板底部工具栏唯一命中），确认弹窗按钮 `.boss-btn-primary`。
