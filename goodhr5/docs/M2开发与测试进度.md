## 第四轮：计划启用与停止意图

- 接通 `/api/execution-plans/{id}/arm` 和 `/stop`。启用复用保存时的真实设备、岗位、平台及会员权限检查；按刚核对的配置版本提交，不沿用并发编辑前的权限结论。启用只返回 enabled 与独立 activation_id，不提前创建运行或操作页面。
- 内存与 PostgreSQL 保存原请求结果及内容摘要。同一请求重试返回同一批次，换内容拒绝；停止指定原批次，旧停止请求重放不覆盖后来的启用。重新启用生成新批次，未来本地从第一项创建新运行。
- 编辑、删除、启用与停止共用计划行锁。启用后需先停止再编辑；停止立即关闭未来触发，但有未结算运行或尚未释放的账号占用时保留 stop_requested，继续禁止编辑及重新启用。
- 真实 PostgreSQL 与内存契约、HTTP 路由验证通过。实际并发编辑与启用只有一个成功；终态运行仍持有 releasing 占用时，用户停止不会清掉占用或开放编辑。明确启用独立 M2 PG 的完整 httpapi 回归通过。

## 第五轮：停止收尾确认

- 云端新增 `/api/execution-plans/{id}/confirm-stop`，复用原计划请求回执表；确认必须匹配真实会话、指定绑定电脑、原配置版本、原启用批次和 cleanup_confirmed。未确认、换电脑或借用旧批次不能解除保护。
- PostgreSQL 先锁账号，再锁计划行，核对关联占用已实际释放。收尾确认和父运行、子项结算及解除 stop_requested 同一事务保存；跨窗口 waiting_window 记录可结算，原动作计数保留。结束时间和状态序号同步写入。
- 成功确认重试返回原结果，不重复推进序号；原确认迟到不影响重新启用的新批次。内存模式对终态但仍持有占用的运行补齐同样保护。
- 真实 PG 验证实际领取后未释放仍拒绝确认，按原凭证安全释放后才能结算并编辑；内存及 HTTP 验证缺少收尾确认、其他电脑、重复回执与迟到旧批次。
- 本地调用方仍待接入，不能把云端确认 API 已通过测试等同于实际页面收尾已验收。统一启动、计划调度、报告、前端及完整 Windows 场景仍未完成。

## 第七轮：递增状态与安全释放

- 接通运行 GET、`/{id}/status` 与 `/{id}/release`。开始确认后才保存首次 started_at；进入 draining 保留账号占用并标为 releasing。状态序号必须递增，主项游标不倒退；进入收尾后不能绕回 running，需要实际释放并重新领取。
- 释放确认将运行状态、账号释放和两类原请求回执同事务提交。waiting_window 保持运行未结算及原首次开始时间；completed、incomplete、stopped、blocked 保存结束时间。收尾结果失败不会单独清空账号。
- 用户停止后拒绝继续运行或进入下一窗口，只允许安全停止或故障收尾；解除计划编辑保护仍须单独完成计划停止确认。失去绑定的原电脑不能继续运行，但仍可凭原占用证明清理并释放。
- 内存与真实 PG 验证从领取到开始、收尾、窗口等待、重新领取和完成；重复回执不推进序号，迟到旧释放不能清掉新占用，原开始时间与游标保留。PG 并发低序号不覆盖高序号，释放回执冲突完整回滚状态和占用；HTTP 验证设备解绑后的继续执行拒绝与安全释放成功。
- 本轮修正 PostgreSQL 时间精度导致的首次回执与后续重读不一致：回执使用数据库实际保存的时间。`go test ./... -count=1` 后端回归通过，明确启用独立 M2 PG 测试；其他历史集成仍受各自 DSN 控制。上述验证仍不替代本地页面收尾、动作计数补传或 Windows 实际多岗位验收。
- 后续继续接入本地生命周期、每个独立执行项的动作计数、后台时钟、跨窗口恢复、报告和前端；M2 尚未完成。

## 第八轮：独立执行项与动作进度

- 当天运行首次领取时，同事务初始化每条 item_run_id。允许同一岗位重复出现，各项保存独立编号、不可变岗位编排快照、主项状态和分动作数量，不按岗位合并。未开始动作保持 pending，不初始化为 active。
- 状态接口接受完整执行项进度；校验原编号、已选动作、主项顺序、递增数量及未知结果。未知结果不计入成功数量。先完整校验，再同事务保存父状态、全部子项与占用；输入 map 的后续修改不能污染内存存储。
- 主项 completed 与消息动作 active 独立：前项已激活回复可在后项执行时继续计数；未开始的后项和已经越过却未激活的动作不能偷偷激活。所有当前动作未结束时拒绝声明整次 completed。
- 窗口等待和重新领取保留原 item_run_id、主项游标、数量及未知结果；次日创建新身份并从零计数，旧运行历史保留。日末、停止或故障结算把未完成主项及已激活动作记为 stopped，未开始动作仍保持 pending，周期计划继续 enabled。
- PostgreSQL 运行详情使用只读可重复读事务获取父子一致快照。真实数据库验证第二个子项写入失败时，第一个子项、父状态和账号占用完整回滚；内存及 PG 共同验证计数倒退、提前激活、前项消息穿插、跨窗口恢复、次日重置、日末不关闭周期计划与历史统计保留。HTTP 拒绝通过进度字段修改岗位快照。
- 这些是云端进度存储与受控模拟测试。本地动作增量转换、原 TaskRun 关联、多岗位页面调度、实际窗口触发、报告与前端仍待接入；没有运行真实招聘操作，M2 尚未完成。

## 第九轮：本地计划契约、通信与安全快照

- 本地新增独立 planmodel，复用已有 planclock.Schedule；计划、原当天运行、独立执行项、动作计数与安全占用快照均使用明确类型，不包含登录令牌或占用凭证。
- 本地云端客户端接通计划列表、原运行读取、原编号领取及状态/释放。返回值必须匹配运行、批次、版本、日期、占用者和执行电脑；泛成功、身份不匹配或序号不匹配不能确认许可。请求凭证只用于发送，普通与调试格式均隐藏凭证。
- 复用现有 HTTP 传输，为计划接口启用精确整数解析；不改变原接口的数字类型。测试验证大于 2^53 的状态序号与动作计数不被浮点转换截断。账号占用返回稳定 EXECUTION_BUSY 错误码，登录过期复用原 AuthExpiredError。
- SQLite 增量建立按已核对账号作用域隔离的 plan_cache 和 plan_run_snapshots。全部字段带中文说明，安全快照无令牌或占用凭证列。旧计划序号、身份变更、同版本换配置、计数倒退和同日批次换 run_id 均拒绝；可按原批次日期找回运行，缓存不是启动许可。
- 真实 SQLite 关闭重开验证原编号、重复岗位独立项、计数、未知结果与大整数保留；另一账号无法读取。客户端使用独立 HTTP 夹具验证原请求重试、返回身份、明确等待、登录过期及凭证日志隐藏；未访问招聘页面。
