## 第七轮：递增状态与安全释放

- 接通运行 GET、`/{id}/status` 与 `/{id}/release`。开始确认后才保存首次 started_at；进入 draining 保留账号占用并标为 releasing。状态序号必须递增，主项游标不倒退；进入收尾后不能绕回 running，需要实际释放并重新领取。
- 释放确认将运行状态、账号释放和两类原请求回执同事务提交。waiting_window 保持运行未结算及原首次开始时间；completed、incomplete、stopped、blocked 保存结束时间。收尾结果失败不会单独清空账号。
- 用户停止后拒绝继续运行或进入下一窗口，只允许安全停止或故障收尾；解除计划编辑保护仍须单独完成计划停止确认。失去绑定的原电脑不能继续运行，但仍可凭原占用证明清理并释放。
- 内存与真实 PG 验证从领取到开始、收尾、窗口等待、重新领取和完成；重复回执不推进序号，迟到旧释放不能清掉新占用，原开始时间与游标保留。PG 并发低序号不覆盖高序号，释放回执冲突完整回滚状态和占用；HTTP 验证设备解绑后的继续执行拒绝与安全释放成功。
- 本轮修正 PostgreSQL 时间精度导致的首次回执与后续重读不一致：回执使用数据库实际保存的时间。`go test ./... -count=1` 后端回归通过，明确启用独立 M2 PG 测试；其他历史集成仍受各自 DSN 控制。上述验证仍不替代本地页面收尾、动作计数补传或 Windows 实际多岗位验收。

## 第八轮：独立执行项与动作进度

- 当天运行首次领取时，同事务初始化每条 item_run_id。允许同一岗位重复出现，各项保存独立编号、不可变岗位编排快照、主项状态和分动作数量，不按岗位合并。未开始动作保持 pending，不初始化为 active。
- 状态接口接受完整执行项进度；校验原编号、已选动作、主项顺序、递增数量及未知结果。未知结果不计入成功数量。先完整校验，再同事务保存父状态、全部子项与占用；输入 map 的后续修改不能污染内存存储。
- 主项 completed 与消息动作 active 独立：前项已激活回复可在后项执行时继续计数；未开始的后项和已经越过却未激活的动作不能偷偷激活。所有当前动作未结束时拒绝声明整次 completed。
- 窗口等待和重新领取保留原 item_run_id、主项游标、数量及未知结果；次日创建新身份并从零计数，旧运行历史保留。日末、停止或故障结算把未完成主项及已激活动作记为 stopped，未开始动作仍保持 pending，周期计划继续 enabled。
- PostgreSQL 运行详情使用只读可重复读事务获取父子一致快照。真实数据库验证第二个子项写入失败时，第一个子项、父状态和账号占用完整回滚；内存及 PG 共同验证计数倒退、提前激活、前项消息穿插、跨窗口恢复、次日重置、日末不关闭周期计划与历史统计保留。HTTP 拒绝通过进度字段修改岗位快照。
- 这些是云端进度存储与受控模拟测试。本地动作增量转换、原 TaskRun 关联、多岗位页面调度、实际窗口触发、报告与前端仍待接入；没有运行真实招聘操作，M2 尚未完成。
